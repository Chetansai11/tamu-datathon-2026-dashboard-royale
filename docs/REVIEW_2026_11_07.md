# Independent review for the dashboard enhancement

Reviewed on November 7, 2026 against organizer release `0.9.0-draft`, commit `5f9274bdc3efa6614e6c081becaeadda34c57a32`.

The existing project contains a substantial, useful analytical foundation. The enhancement retains the original offline `dashboard/`, analytical `src/`, tests and provenance. The new interface belongs in `web/` rather than replacing the original bundle.

## Preserve these strengths

- `metrics.py`: active dated placements, scheduled DST exposure, ratios of sums, configured payout variance, explicit partial-cost contribution.
- `q1_decomposition.py`: five-component additive attribution; an improvement over the earlier peer index where floor fallback confused location and machine weakness.
- `forecast.py`: model choice inside the training period, frozen 61-day holdout, constant baseline, calibrated-before-test uncertainty and actual coverage.
- `q3_downtime.py`: comparable full-hour demand pools, dated locations, machine-meter reconciliation, exact waiting-time overlap by clock shift, and displacement sensitivity.
- `q4_q5_players.py`: person-level aggregation across 21 whole-month windows, stable starting demographics, fixed benefit/tier comparisons, and no duplicated comp cost.
- `q6_actions.py`: constrained catalog costs, lead times, retained capital, zero guaranteed inspection uplift and explicit alternatives.
- Existing source-oriented evidence cards, reproducibility tests, offline original bundle and source provenance.

The `toolkit/` folder is reusable starter infrastructure for generic EDA, dashboards, models, APIs and reinforcement-learning games. It is not the deployed challenge analytical path and remains untouched. No toolkit API clients were invoked and no credentials were read.

## Interpretation corrections for the enhanced presentation

- Prefer **“Pause blanket replacement; inspect one payout signal and test Back Forty access.”** “Proven cause,” “fix the leak” and “the machines aren't the problem” overstate what observational comparisons establish.
- The positive combined machine component does not establish that each of the ten machines is healthy. Some individual descriptive machine factors are below one.
- “Nine candidates spent time in Back Forty” handles historical and retired placements more accurately than implying all are there at the July decision date.
- A 0.72-point signage break-even assumes no displaced play, June operating capacity and June seated-play economics. Display the displacement condition beside the result.
- A payout-screen flag supports inspection; no misconduct, defect or guaranteed repair benefit is established.
- The decomposition's daily floor/game rates exclude the target. Its monthly zone factor removes target rows but uses shared game-mix rates; describe it as retrospective and descriptive, not universally cross-fitted.
- Show guest cohorts at whole-month grain and fixed full-investigation evidence separately from filter-responsive exploration.

## Concrete implementation findings

1. `src/package_release.py --rebuild` and README reproduction commands omitted `src.q1_decomposition`. On a fresh rebuild, actions could fail due to a missing report or retain a stale decomposition after a refresh. Insert the module before actions are generated.
2. The enhanced portfolio picker initially used `retireDate`, but its machine schema exposes `lastActiveDate`. July action targets and affected bank members must be active on June 30.
3. The enhanced action budget must describe simulated spend as **proposed**, not deployed. Use the canonical shift identifier `grave`.
4. Nonfinite numeric inputs must be rejected by budget validation instead of coercing `NaN` to zero.

Items 2–4 were reported to the interface owner for correction. The release-dependency omission is fixed under coordination task T298f. Public hosting, browser appearance, keyboard behavior and a recorded walkthrough are separate verification steps; this review does not claim them.
