# Claims and evidence

Scope: synthetic Gilded Ace casino activity, January 1–June 30, 2025; hypothetical planning horizon July 1–30. Currency: USD. Source release: `0.9.0-draft`, organizer commit `5f9274bdc3efa6614e6c081becaeadda34c57a32`. The retained team report bundle is `dashboard/reports.json`; the enhanced app preserves these reports and their source pointers. The investigation is fixed to the full period, while exploratory floor metrics and monthly guest windows respond to the stated filters.

## Measurement plan

**Inspection.** Archive M-1158 configuration and meters, independently recompute the payout benchmark, then record a documented inspection disposition on July 2. If a correctable discrepancy is confirmed, obtain a separate implementation estimate before releasing reserve funds. Track configuration compliance and subsequent actual-minus-theo with modeled variance; do not declare success merely because one month's hold rises.

**Wayfinding.** Before implementation, fix June baselines, weekday comparisons and comparison zones (Garage Entrance and Hotel Corridor). Measure July 11–30 covered sensor crossings, occupancy and theo per available hour. Compare changes with the prespecified zones and the whole-floor weekday benchmark. Check for displaced play; a zone-level increase without property-level gain does not establish budget payback. Report effect uncertainty and adverse or null results. Sensor crossings are not unique visitors.

## Independent review performed for the enhancement

Fresh organizer Parquet was used to independently check 55,092 on-floor rows, 1,018 excluded rows, all 181 daily coin/payout/win/theo totals, both holdout MAEs, per-person top-1% wager share and ahead rate, all ten displayed decomposition identities, the catalog-priced funded plan, and both displacement break-even examples. These passed.

The original repository's complete 45-test regression suite was also rerun successfully (86.01 seconds), using pinned, SHA-verified hourly meters, redemption-ledger and POS files in addition to the core inputs. This covers hourly/daily/ticket downtime reconciliation, guest cohort conservation, comp ledger/POS links, forecast leakage, machine diagnostics, source accounting and original dashboard JavaScript bindings. The historical 62-file/31-table full-format parity audit remains a retained provenance result; this enhancement did not download and recompare every raw CSV counterpart. Browser visuals, final hosting and the enhanced interface's separate checks are not established by these analytical tests.

For further semantics and limitations, see [METHODOLOGY.md](METHODOLOGY.md). The standalone UI package, source and final hosting verification are separate deliverables.
